# NetPulse v1.6.7

**Maintenance release. No user-visible change: fewer moving parts behind the settings screen.**

### 🧹 Cleaned Up

- **Removed dead code left over from earlier fixes.** `DayKeys.nextMidnightMs` was only referenced by its own two unit tests — the day-key ticker re-checks on a bounded 30 s interval instead of sleeping to midnight, so nothing in production needs it. `UsageRepository.getTodayUsage` was declared, implemented and never called, because every consumer observes the flow.
- **Closed a latent lost update in `updateMeterPreferences`.** It read the stored preferences *outside* the `edit` transaction and wrote the result back inside it, so two concurrent setters could both transform the same snapshot and the second write silently dropped the first one's change. The transform now runs against a snapshot built inside `edit`, and the snapshot builder `meterPreferencesOf` is shared with `meterPreferencesFlow` so the defaults are defined once.

The window was narrow — every caller today is already serialized through the ViewModel — but it was a real correctness hole in a function whose job is to not lose settings.

### ✅ Verified

- 76 unit tests (78 − the 2 that covered `nextMidnightMs`), 0 failures.
- 0 lint errors on debug; 18 warnings, unchanged from v1.6.6.
- Device proof on `emulator-5554`: toggled **Unit in Bits** and **Pause When Screen Off** back to back, both landed, and both survived a `force-stop` + relaunch. The home screen rendered `Kbps` instead of `KB/s`, confirming the persisted value drives the UI. Both settings were restored to their defaults afterwards.
