# NetPulse v1.5.0

**No more silently dropped bytes when the network is mid-handover or behind a VPN.**

### 🐛 Fixed

- **Usage accounting discarded bytes whenever the active transport was neither Wi-Fi nor mobile.** `recordConsumption()` called `consumeDelta()` — which clears the pending counters — *before* deciding which bucket the bytes belonged to. Any tick where the transport resolved to `NONE` or `OTHER` hit an empty `else -> Unit` and those bytes were gone for good.
- That path is reachable in normal use. `NONE` is what the platform reports during a Wi-Fi ↔ cellular handover and before the first network attaches after boot. `OTHER` is what an always-on VPN looks like, because VPN capabilities carry the VPN transport instead of the physical one — so a VPN user's entire session could record zero while the notification reported healthy speeds.
- The decision now happens before the counters are cleared. Bytes measured while the transport is unknown are **held** and attributed on the next tick. Transports with no bucket (`ETHERNET`, `OTHER`) are dropped explicitly rather than by accident, and held bytes are capped at 64 MB so a long outage cannot dump an arbitrary figure into a later day.

### ✅ Verified

- 50 unit tests green (up from 42), 0 lint errors.
- New pure `attributeUsage(type, deltaBytes, heldBytes)` rule with 6 tests, plus 2 new `TrafficDataSource` tests proving `peekDelta()` observes the same bytes twice and that held bytes survive into the committed total.
- On-device: 8,000,205 B transferred inside the emulator → ledger grew 8,281,951 B. A 40 MB transfer interrupted by disabling Wi-Fi recorded 11,920,639 B against 11,938,537 B of interface traffic — no gap, and both the `mobile` and `wifi` buckets ended up written.
