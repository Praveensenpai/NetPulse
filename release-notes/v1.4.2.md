## 🔍 NetPulse v1.4.2 — Status Bar Number You Can Actually Read

The speed glyph was being sized by the width of its worst-case label, which left most of the square canvas empty and made the number look half the height of the clock next to it.

### 🔧 Fixed

**The status-bar speed number now fills the icon height.** `SpeedIconGenerator` sized the font so that a four-character worst case (`000B`) fit the canvas width. Because the platform scales the whole square bitmap into the status-bar slot, the unused vertical space shrank every reading — `0B` rendered at roughly a quarter of the canvas height.

The font is now sized from the canvas **height**, and excess width is absorbed per label with a horizontal scale (floored at 0.6 so text stays legible). Height is identical for every reading, so the glyph no longer changes size as the number changes. The unit letter is still always shown.

### 📏 Measured on device

| Reading | Ink before | Ink after |
|---|---|---|
| `0B` | 19 x 14 px | 32 x 24 px |
| `3.3M` | — | 39 x 24 px |

That is a 71% increase in glyph height, putting it at 86% of the system clock's cap height instead of 50%. The four-character `3.3M` label was captured mid-transfer to confirm the squeeze path does not clip.

### ✅ Verified

- Before/after screenshots at 5x and 8x magnification, same crop and threshold.
- `0B` and `3.3M` both render at exactly 24 px ink height — no height variation between readings.
- Unit tests green, lint 0 errors, `assembleDebug` and `assembleRelease` green.
