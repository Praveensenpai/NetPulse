## 🎯 NetPulse v1.3.0 — Midnight-Accurate Per-App Totals

Per-app usage now stops importing yesterday's bytes into today.

### 🔍 The Problem

Android stores network counters in fixed buckets, and a bucket is only returned when it sits **entirely** inside the query window. Measured on a real device, the bucket grid is **:30-aligned**, so the first bucket of any day runs **23:30 → 01:30** — 30 minutes of yesterday, 90 minutes of today.

Since a bucket cannot be split, counting it whole overstated "today" by up to 30 minutes of yesterday's traffic, for every app active around midnight.

### ✨ The Fix

NetPulse runs as a foreground service, so it is normally alive at midnight. It now snapshots each app's **cumulative** byte total as the day turns, then reports `current - baseline` — the exact today-only figure, no bucketing involved.

If the service started later in the day, there is no baseline to take, so it falls back to the previous whole-bucket sums. Earlier bytes are never subtracted away.

### 🧪 Verified

- **26 unit tests** covering the day filter and the baseline window (`withinBaselineWindow`).
- Lint clean, `assembleDebug` and `assembleRelease` green.
- Live on device: **1.1 MB/s** reported during a 2 MB transfer, PID stable, no exceptions.

### 📦 Install

```bash
adb install NetPulse-v1.3.0.apk
```

### ⚠️ Known Limit

Samsung's bucket duration differs from AOSP, so the size of the straddle window varies by device. The baseline path removes the error entirely whenever the service is running at midnight; the fallback keeps the old behavior. ReVanced accuracy on the S20 FE is still unmeasured — the device was offline during this release.
