## 📋 NetPulse v1.4.4 — Live Usage List That Isn't Empty After a Restart

Right after the service started, the Live App Usage card could read "Waiting for the first sample…" for minutes while the Usage Log directly below it listed the whole day. The two cards disagreed about the same data.

### 🐛 Root cause

netstats publishes per-UID buckets lazily. On the first poll it returns each package *key* with **0 bytes** — the bucket behind it does not exist yet. The live list is built from that sweep and skips any package with a zero total, so the card stayed empty until real buckets appeared. The Usage Log was unaffected because it is persisted history, not a live measurement.

### 🔧 Fixed

**The live list is now seeded from today's persisted log on the first poll.** A seed survives until the sweep reports a *positive* total for that package, then the real measurement takes over. Seeds are held for at most three minutes and cleared on `reset()`.

The first attempt at this shipped in an uncommitted build and was wrong in an instructive way: it dropped a seed as soon as the package key appeared in the sweep, which is exactly the 0-byte case it was meant to cover. Testing caught it — the card was still empty after a restart. `seededRows()` now tests the measured *value*, not key presence.

Two small pure functions carry the logic, both unit-tested:

- `seedTotals(log, dayStart)` — sums today's log rows per package, excluding yesterday's rows and zero-byte rows.
- `seededRows(seeded, measured)` — keeps a seed until the sweep reports a positive total.

### 📏 Measured on device

`emulator-5554`, clock pinned at 12:06 so the day boundary could not move:

| After restart | Live App Usage |
|---|---|
| before | "Waiting for the first sample…" |
| after | 8 rows at `0 B/s`, matching the `12:00` log entries |

Once real buckets arrive the rates populate normally (`YouTube 388 KB/s`, `Google Play services 4.6 KB/s`, six more).

### ✅ Verified

- 8 new unit tests for the seed functions, full suite 47/47 green.
- Lint 0 errors, `assembleDebug` and `assembleRelease` green.
- Before/after device captures with a pinned clock.
