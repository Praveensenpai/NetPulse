# NetPulse v1.6.3

**Turning off "Show Upload Speed" now removes it from the floating overlay too.**

### 🐛 Fixed

- **The floating mini overlay ignored the "Show Upload Speed" setting.** `FloatingOverlayManager.updateSpeed()` built its text with `SpeedFormatter` directly and always concatenated `↓ … ↑ …`, so the pill kept rendering the upload half no matter what the preference said. The notification and the Home gauge both read `currentPreferences.showUploadSpeed`; the overlay was the one surface that never asked for it.
- **The fix:** the label rule moved into a new pure `OverlayLabel.format(download, upload, unitInBits, showUpload)`. `updateSpeed()` gained a `showUpload` argument, `NetPulseService` passes `currentPreferences.showUploadSpeed`, and the manager's unused `SpeedFormatter` import was removed. Four new `OverlayLabelTest` cases fail the build if upload is rendered while the setting is off.

### ✅ Verified

Overlay windows are excluded from `uiautomator`, so the pill was measured by decoding the screencap PNG in pure Python and taking the extent of its background colour run (`Color.argb(220, 20, 24, 33)`). Fresh process per run on `emulator-5554`:

| Build | `show_upload_speed` | Pill width | Pill x-range |
|---|---|---|---|
| pre-fix | `false` | **367 px** | 102..468 |
| fixed | `false` | **193 px** | 102..294 |
| fixed | `true` | **351 px** | 102..452 |

The first row is the defect: upload disabled and the pill still carried the upload half. The second row is the upload half removed. The third row is the positive control — with the setting on, the upload half is still rendered.

70 unit tests, 0 failures; 0 lint errors on debug and release (18 warnings each).
