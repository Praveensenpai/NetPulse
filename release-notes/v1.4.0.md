## 🩹 NetPulse v1.4.0 — Nothing Lost Across a Restart

The usage log no longer forgets traffic that happened while the service was down.

### 🐛 Fixed

**Bytes moved while NetPulse was not running were silently dropped.** The first poll after any start only recorded each app's total; with no previous value there was no delta, so nothing was logged. A reboot, a killed service, or a force-stop erased that window from the log permanently.

The tracker now persists a per-app totals snapshot and, on the next start, uses it as the previous total — but only when it is safe: same accounting mode, same day, not from the future, and no older than 5 minutes. Anything else is discarded, because subtracting mismatched totals would invent bytes.

Two further defects surfaced during device testing:

- The first poll replaced the recovered baseline with its own partial sweep (16 apps per poll), so any app the sweep had not reached looked new and lost its downtime bytes. A short carry window now keeps adopted baselines until the sweep supersedes them.
- Snapshots were being written before the sweep had covered every app, so the persisted map was incomplete. Persistence is now gated on a complete sweep.

The log and the snapshot are written in a single DataStore edit, so a crash cannot leave them out of sync.

### ✅ Verified

- Device test, byte-exact: 12,000,206 B fetched while the app was force-stopped, then the app restarted. Log row `08:04 YouTube 12,465,112 B` against a netstats delta of 12,465,112 B for that UID.
- 40 unit tests green (6 new for snapshot adoption and the carry merge).
- Lint clean, `assembleDebug` and `assembleRelease` green.

### 📦 Install

```bash
adb install NetPulse-v1.4.0.apk
```

### ⚠️ Known Limit

The recovery window is deliberately 5 minutes. A longer outage cannot be attributed to a single minute row without misreporting when the bytes were used, so it is left unlogged rather than guessed. ReVanced accuracy on the S20 FE remains unmeasured — the device has been offline for every release so far.
