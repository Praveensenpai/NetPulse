# NetPulse v1.6.8

**Correctness release. Under heavy traffic the usage ledger could under-count by a wide margin.**

### 🔒 Fixed

- **Lost byte increments under concurrent sampling.** The byte baseline and pending delta inside `TrafficDataSource` are read-modify-write state, and they were touched from two threads: the 1 Hz polling loop on `Dispatchers.Default` calls `sample` / `peekDelta` / `consumeDelta`, while `reset` and `catchUp` arrive on the main thread from service callbacks. Coroutine cancellation is cooperative, so a tick that is already running keeps executing after `stopMonitoring()` nulls the job and can overlap the next `catchUp()` on resume. Two callers could count the same bytes twice or drop an increment entirely.
  Every public method is now `@Synchronized`. At 1 Hz the monitor is uncontended in practice, so this costs nothing measurable.

The defect reproduces as a deterministic unit test: 8 threads, 2,000 rounds each, 16 B per round. Expected 256,000 B, unsynchronized run recorded 272,672 B. With the fix, five consecutive `--rerun-tasks` runs pass clean.

### ✅ Verified

- 77 unit tests, 0 failures, including a new concurrency test that fails without `@Synchronized` and passes with it.
- 0 lint errors on debug; 18 warnings, unchanged from v1.6.7.
- Device proof on `emulator-5554`: installed `versionCode=29`, launched, toggled **Unit in Bits** (home screen switched between `B/s` and `bps`) and **Pause When Screen Off**. Both landed in the stored preferences and both survived a `force-stop` + relaunch. 0 crash records in the logcat buffer afterwards. Settings restored to their defaults.
