# NetPulse v1.6.1

**Reset now means reset — Today and All Time stay in agreement.**

### 🐛 Fixed

- **"Reset Today's Data Usage" zeroed the day but not the lifetime counters.** All Time is read from the monotonic `lifetime_mobile` / `lifetime_wifi` counters, not from the day buckets, so the reset only ever cleared half the record: the Home screen would show `Today 0 B` directly above an All Time total that still contained the bytes you just deleted, and the next tick added new traffic on top of the stale counter. `resetUsage()` now subtracts the discarded pair from the counters in the same `edit` that zeroes the day.
- **The subtraction is clamped at zero.** A day bucket written by a build that predates the counters can be larger than the counter value; subtracting naively would drive the counter negative and corrupt every later read. `UsageAggregator.reducedLifetime` handles both the normal and the clamped case, and is unit-tested without an Android context.

### ✅ Verified

- 66 unit tests, 0 failures; 0 lint errors on debug and release (18 warnings).
- Measured on `emulator-5554` against a seeded ledger — `usage_2026-11-02_mobile = 1,000,000 B`, `_wifi = 2,000,000 B`, `lifetime_mobile = 50,000,000 B`, `lifetime_wifi = 80,000,000 B`:

  | | Mobile | Wi-Fi |
  |---|---|---|
  | All Time before | 47.7 MB | 76.3 MB |
  | All Time after | 46.7 MB | 74.4 MB |
  | Difference | 1,000,000 B | 2,000,000 B |

  Today read `0 B` after the reset. The stored protobuf confirms the same numbers independently: both day keys `0`, `lifetime_mobile = 49,000,000`, `lifetime_wifi = 78,000,000`.
