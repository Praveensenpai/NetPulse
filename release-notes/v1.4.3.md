## 📐 NetPulse v1.4.3 — Status Bar Number Level With The Clock

v1.4.2 switched the glyph from width-first to height-first sizing, but left the horizontal squeeze floor at 0.6. That floor was itself the binding constraint, so the number stopped at 24 px while the clock beside it was 28 px.

### 🔧 Changed

**`MIN_TEXT_SCALE_X` lowered from 0.6 to 0.5.** The font size is `min(byHeight, byWidth / MIN_TEXT_SCALE_X)`, and at 0.6 the second term was still the smaller one. Dropping the floor to 0.5 raises the width budget enough that the height term becomes reachable, so the glyph fills the icon the way it was always meant to.

Nothing else moved. Height is still computed once from the worst case, so it stays identical across every reading. Only four-character labels (`2.8M`, `1.8K`) actually use the floor; short ones still draw at natural width.

### 📏 Measured on device

Eight frames captured mid-transfer on `emulator-5554`, same crop and 35% threshold:

| Reading | v1.4.2 | v1.4.3 |
|---|---|---|
| `0B` | 32 x 24 px | 38 x 28 px |
| `2.8M` | 39 x 24 px | 39 x 28 px |

Glyph height is now 28 px, exactly level with the clock's 28 px cap height, and double the 14 px it started at.

### 🔍 Legibility check

`2.8M` was inspected at 7x zoom. The decimal point survives as a distinct sliver, the `2` counter and the `M` apex stay open, strokes do not merge, and there is no clipping on any edge. This is the tightest the label gets, and it holds.

### ✅ Verified

- Eight consecutive frames all measured 28 px tall — height does not vary with the reading.
- Unit tests green, lint 0 errors, `assembleDebug` and `assembleRelease` green.
