# NetPulse v1.6.4

**Traffic that happens while the screen is off now counts against your usage again.**

### 🐛 Fixed

- **Every byte transferred during a screen-off pause was silently discarded.** `NetPulseService.startMonitoring()` called `trafficDataSource.reset()` on each resume, which throws away the byte baseline `TrafficStats` is measured against. The next `sample()` re-baselined with no previous value and reported zero, so the whole paused interval vanished from the ledger. Bytes that move while the app legitimately pauses are still your usage; the meter was simply refusing to count them.
- **The fix:** `TrafficDataSource.catchUp()` folds the gap into the pending delta and re-baselines, so the paused bytes are recorded once while the next tick's rate stays normal. `startMonitoring()` uses `catchUp()`; `stopMonitoring()` keeps the hard `reset()` so a window where you switched monitoring off is never attributed. Four new `TrafficDataSourceTest` cases cover the gap, the no-speed-spike behaviour, counter resets, and the pre-first-sample no-op.

### ✅ Verified

Measured on `emulator-5554` with a paused screen (`pause_when_screen_off = true`, `mWakefulness=Asleep` confirmed), 20 MB pulled over `wlan0` during the pause, then woken and allowed to settle:

| Build | `wlan0` bytes during pause | Ledger growth after wake |
|---|---|---|
| v1.6.3 | +20,750,690 | +96 B |
| v1.6.4 | +20,750,486 | +20,765,766 B |

74 unit tests, 0 failures; 0 lint errors on debug and release.
