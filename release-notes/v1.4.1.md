## 🩹 NetPulse v1.4.1 — Snapshots That Actually Keep Saving

A regression introduced in v1.4.0 stopped the usage snapshot from ever being written after the first minute.

### 🐛 Fixed

**Zero-byte packages were treated as "not yet swept", so the sweep never finished and snapshots stopped being persisted.** v1.4.0 gated snapshot writes on a complete sweep, but the result map dropped entries whose byte count was 0. The next poll treated those packages as still pending, re-queued them, and found 0 again — forever. `sweepComplete()` never returned true, so the recovery snapshot silently froze minutes after startup and restart-gap recovery stopped working.

The result map now keeps every swept package, including 0 B ones, so a completed sweep is distinguishable from an unfinished one. The UI filters zero-byte packages itself, so the live list is unchanged.

### ✅ Verified

- Live device check: snapshot header advanced `1793157389294` → `1793157450096` → `1793158622495`, confirming writes continue past the first minute.
- Live App Usage renders no zero-byte rows; the usage log keeps writing fresh minute rows.
- 39 unit tests green, lint 0 errors, `assembleDebug` and `assembleRelease` green.
