# NetPulse v1.4.9

**The sampler now respects the screen you actually have, not the one it assumed.**

### 🐛 Fixed

- **Polling continued with the screen off after any start that happened while the display was already dark.** The service held `isScreenOn = true` as a starting assumption and only ever changed it from screen on/off broadcasts. Registering a receiver delivers future transitions only — it never reports the current state — so a start during screen-off (boot with *Start on boot*, `MY_PACKAGE_REPLACED` after an update, or a `START_STICKY` restart) took the "screen is on" branch and kept sampling, and kept spending battery, until the user happened to cycle the display.
- The screen state is now read from `PowerManager.isInteractive` on every decision instead of cached. The rule itself is a two-line pure function, `shouldPoll(pauseWhenScreenOff, screenOn)`, so it is unit-tested rather than trusted.

### ✅ Verified

- 42 unit tests green, 0 lint errors.
- Reproduced on device first: screen asleep, `pauseWhenScreenOff` on, service started — the usage ledger grew by 4,996 B over 25 s of background traffic.
- After the fix, same scenario: ledger byte-identical across 30 s with `mWakefulness=Asleep`, then growth resumed on `KEYCODE_WAKEUP` with `mWakefulness=Awake`.
